# cartoonforge

Cartoons drawn by code, frame by frame. No video model. Output: a 1080×1920, 24 fps MP4 with
voice, music and burned-in captions, ready for Reels, plus a contact sheet to review it.

`SKILL_DIR` below = this skill's folder.

## Requirements

Node ≥ 22, FFmpeg, Google Chrome (or Chromium). Voice: `pip install kokoro soundfile` for the good free
voice (Apache-2.0); without it the skill uses macOS `say` or espeak-ng (robotic — drafts only).
If something is missing, tell the user exactly what to install; don't build the video another way.

## Workflow

### 1. Brief → beat sheet (before any code)
Settle with the user, or decide and state: topic, style, length (10–20 s for a Reel), voice
(TTS or their recording), language, ending. Then write a beat sheet: 4–7 beats with time ranges,
one clear action each, aligned with what the voice says.
- Hook in the first 1.5 s (title card, gag or motion).
- Anticipation before every big action, settle after it.
- End on a card or a pose that loops.

### 2. Pick the style
`ls SKILL_DIR/runtime/styles`. Read `runtime/styles/<style>/README.md` in full (look, timing, do/don't)
and `style.json` (music genre, voice treatment). If the requested style doesn't exist, say so, offer
the closest one, or create it (step 7).

### 3. Scaffold
```bash
node SKILL_DIR/scripts/new-film.mjs <slug> --style <style> --title "<Title>"
```
Creates `./cartoons/<slug>/`: `index.html` (a working starter film), `script.json`, `cf-data.js`, `lib/`.

### 4. Words, voice and music → `script.json`, then `audio.mjs`
```jsonc
{
  "lang": "en",                 // en, es, fr, it, pt, ja, zh, hi with Kokoro; ru/de/pl via espeak/say
  "voice": "af_heart",          // Kokoro voice: af_heart, af_bella, am_michael, bf_emma, bm_george…
  "start": 1.8, "gap": 0.35,    // first line after the title card; pause between lines
  "lines": ["Hi! I'm Pip.", {"text": "Watch this!", "at": 5.0}],
  "recording": null,            // or "my-voice.m4a" — the user's own voice instead of TTS
  "voiceFx": "style",           // style | none | gramophone | radio | cartoon | chipmunk
  "music": true,                // true = generated in the style's genre; false; or a path to a file
  "musicVolume": 0.55,
  "minDuration": 10
}
```
- Keep lines short: 3–9 words each. They become the captions.
- **Own voice**: copy the user's file into the film folder and set `"recording"`. Put the text in
  `lines` too if you know it — used for captions when automatic transcription isn't available.
  The style treats the voice (e.g. gramophone for 1930s); it is stylisation, never cloning someone else.
- **Music**: generated by code, so it's free to use. If the user wants a trending Instagram sound,
  set `"music": false` and tell them to add it in Instagram when posting.

```bash
node SKILL_DIR/scripts/audio.mjs cartoons/<slug>
```
Writes `assets/soundtrack.wav` (voice + ducked music, −14 LUFS), `cf-data.js` (duration + caption cues)
and wires the soundtrack and new duration into `index.html`. Run it again after any change to the script.

### 5. Animate → `index.html`
The whole film is `render(t)`, a pure function of time. `CF.duration` and `CF.captions` come from
`cf-data.js`; captions are drawn automatically in the style's lettering. Read
`references/animation-in-code.md` before writing motion. Hard rules:
- **Deterministic**: no `Math.random()` (use `Toon.rng(seed)` / `Toon.noise()`), no `Date.now()`,
  no CSS animations or transitions. Same `t` → same picture.
- Time actions to the caption cues (`CF.captions[i].start`) so the character acts what is said.
- Call `look.update(tRaw)` first, then use `Toon.onTwos(tRaw)` for character motion.
- Keyframes `Toon.track()`, limbs `Toon.hose()`, squash & stretch `Toon.squash()` / the rig's `squash`.
- Keep the action between y≈500 and y≈1500; captions sit near y≈380 (Reels UI covers top and bottom).
- Original characters only (bundled: Pip, `lib/characters/pip/rig.js`). Never draw studio characters,
  logos or famous catchphrases, even if asked; offer an original instead.

### 6. Render and review
```bash
node SKILL_DIR/scripts/render.mjs cartoons/<slug> --draft
```
**Open `renders/<slug>.sheet.png` and look at it** before saying it's done: character on screen and
on model, captions readable and not covering the face, every beat visible. Fix and re-render.
Final: run again without `--draft` (~2–3 min for 10 s on a laptop). Give the user the MP4.

### 7. New style (when asked)
Follow `references/new-style.md`: `runtime/styles/<slug>/` with `README.md`, `style.js`
(`palette`, `motion`, `caption`, `install()`) and `style.json` (name, era, tagline, music, voice).
Prove it with a 10 s film of Pip. In the cartoonforge repo, `npm run showcase -- <slug>` adds it to
the gallery.

## Files

| Path | What |
|---|---|
| `runtime/core/toon.js` | `onTwos`, `track`, `ease`, `squash`, `hose`, `rng`, `noise`, `captions`, `film` |
| `runtime/styles/*/` | style packs |
| `runtime/characters/pip/rig.js` | the mascot rig; header lists `pose()` fields |
| `scripts/new-film.mjs` | scaffold a film (`--update-lib` refreshes an existing one) |
| `scripts/audio.mjs` | TTS / recording + style voice FX + generated music + captions |
| `scripts/render.mjs` | MP4 + contact sheet |
| `references/animation-in-code.md` | principles of animation → code, timing cheatsheet |
| `references/new-style.md` | how to build and validate a style pack |
